# MCLA bench flow, driving (tools/bench.py): free roam in a crowd, then a long drive.
# Ported from the owner's iOS port (tools/mcla/bench_flow.txt: dev008's flow_f60p extended), re-timed for the x86 build from
# the W2.1 bring-up (b2.1, D3D12, after_intro fixture). Run it with the after_intro fixture (run_game.py copies it into a
# fresh user dir).
# Format: <second>:<button>[+<button>...][/<hold ms>], '#' comments; seconds count from process start.
#
# expect: free-roam
# seconds: 360
# fixture: after_intro
#
# 'expect' is the state run_game.py needs to see for exit 0: free-roam = the log shows `[mcla-mode] ... -> free-roam`.
# 'seconds' is the default --seconds (the M4 bench runs 360); the pattern below continues to 444 s. bench.py measures from
# `-> free-roam` + 20 s to the end.
# Timeline on x86 (W2.1): the title ('PRESS start') is first on screen ~27 s after process start (black at 26 s); the first
# Start that takes is the one at 28 s (`Startup_Checks` at ~30.6 s); with the fixture `loading -> free-roam` comes at ~36.5 s,
# and any Start after ~37 s opens PAUSE. So: Start/300 at 28, 30, 32, 34 (a press before the title exists is lost; the title
# polls the pad every 2-4 updates, so Start is held 300 ms), then B taps at 40..49 close a pause a late Start opened (B only
# closes, it never opens one; in free roam it is a harmless handbrake tap). A slower boot than ~34 s misses every Start: the run
# never reaches free roam and bench.py marks it INVALID (its guard stops it at --guard-at).
# T+52 the car drives: throttle held in 14 s slices, a gentle steer inside every slice (busiest street, then a quiet one), and
# an A tap at the end of every slice: a long blind drive ends in a 'DAMAGED OUT / QUICK FIX' modal (~282 s in W2.1) that only
# A answers (Start and B do nothing), so A is tapped every 14 s to dismiss it within one slice. No pause.
