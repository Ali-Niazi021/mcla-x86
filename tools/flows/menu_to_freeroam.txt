# MCLA scripted pad flow: SAVED profile -> title -> free roam -> drive -> PAUSE menu -> drive. 150 s is enough for the
# smoke run; a longer --seconds (the M3 soak uses 600) keeps driving to 590 s (x86 addition below).
# Ported from the owner's iOS port (mac/flows/mcla_menu_to_freeroam.txt), re-timed on x86 by the W2.1 bring-up
# (the 600 s soak ran clean as run w2.1-m3c).
# Syntax: <second>:<button>[+<button>...][/<hold ms>], '#' comments; seconds count from process start.
#
# expect: free-roam
# seconds: 150
# fixture: after_intro
#
# 'expect' is the state run_game.py needs to see for exit 0: free-roam = the log shows `[mcla-mode] <any state> -> free-roam`.
# 'seconds' is the default --seconds. 'fixture' is the user-data copy this flow is made for (run_game.py warns when
# --fixture is missing): $WORK/fixtures/after_intro, a copy of a run's user/ folder holding mc4.sav with the intro, the
# vehicle select and the first cutscene done; the game then loads straight into free roam: no alert, no cutscene.
# run_game.py copies the fixture into a fresh per-run user dir, so the fixture itself is never written.
# On a FRESH user dir this flow stops at the save-game ALERT (use new_profile_to_freeroam.txt for that).
# Timeline on x86 (runs w2.1-m3b/m3c, D3D12 720p): first engine frame ~4 s, the title takes the Start at 28 s, save opened
# ~31 s (`front-end -> loading`), free roam + HUD at ~36.5 s (`loading -> free-roam`, the car stands on the street).
# So there is no Start after 36 s: a later one would open the PAUSE menu (the iOS file had Starts to 44 s for a slower boot).
# Known trap: the title polls the pad every 2-4 updates, so Start is held 300 ms, and repeated because a press before the
# title exists is lost. Do not press Start after the title unless the PAUSE menu is wanted: once the car is in roam Start
# opens PAUSE.
